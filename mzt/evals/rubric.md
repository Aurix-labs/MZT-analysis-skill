# MZT 行为评测 v2

评测目标是观察这套指导思想是否帮助 AI 更好地处理问题：结论是否受事实和约束影响，注意力是否落在影响结果的关键处，条件变化时是否修正。答案中出现理论术语、固定标题、反问或验证章节，都不能单独证明做到了这些。

只评可见答案、实际工具动作、产物及多轮修正。不索取、读取或评分隐藏思维链；也不要求作答者为证明使用技能而转述内部分析步骤。要求解释的题目，检查其提供的可核对理由是否充分。

## Reviewer 的判断依据

先读题目与可用事实，再读完整答复。`evals.json` 中的 `reviewer_expectations` 是判断方向，不是要求作答者逐项展示的输出清单。合理的不同结论可以同样优秀；评价结论为什么适用于这些条件，而非是否猜中预设建议。

| 维度 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|
| 事实与证据 | 虚构背景、数据或来源；将猜测当事实 | 基本区分已知与未知，但关键判断的依据偏弱 | 准确使用已有证据，关键未知有明确边界，必要查证或实际验证支持结论 |
| 目标与约束 | 替换用户目标，忽略明确边界 | 回答主题正确，但部分条件没有影响建议 | 尊重用户任务，期限、资源、权限与既定方向实质影响选择；必要追问聚焦会改变决定的信息 |
| 主次与因果 | 罗列概念或任意宣布一个主要矛盾 | 识别相关因素，但优先级或因果联系不充分 | 找到影响当前结果的关键因素，解释相互作用与优先次序，避免把共现当原因 |
| 可修正性 | 忽视反证，坚持原说法，或无依据反复改口 | 承认新信息，但建议与依据更新不完整 | 根据新证据调整受影响的判断，保留仍成立的部分；需要条件判断时指出会改变结论的具体条件 |
| 表达与任务适配 | 套分析报告，或为简短省掉必要工作 | 基本完成任务，但有填充或关键解释不足 | 交付用户需要的答案、代码或其他产物；简题直接，复杂题有足够理由，遵守指定格式与长度 |

不适用的维度标记 `N/A` 并写明原因。例如乘法题和代码函数题不需要宣布“主要矛盾”；没有多轮反证且不涉及条件选择的事实题，可修正性通常为 `N/A`。不要为了拿满五个维度而反向要求每题写成完整报告。

每个有效评分附一句可见证据（简短原文、动作或产物位置），以及最重要的缺陷或改进。若存在关键事实错误、虚构背景、违背用户明确范围、程序行为错误或忽略关键反证，单独记录任务失败，不能用文风分数抵消。不要仅凭“请确认”判断是否多余停等；要结合任务是否缺少必要信息或授权。

先报告每题成功与失败、各维度分布和典型反例。有需要时可算同一道题适用维度的均值；不把含不同 `N/A` 的题目简单混成一个能力分数。长短不直接决定优劣：第11题有明确上限，第12题要求充分解释，评价标准不同。

## 可机械测量的内容

`check_objective.py` 返回 `schema_version: 2`，只测量：

- `character_count`：Python `len(text)`，包括标点、空白与换行的 Unicode 码点数，不是 token 数。
- `nonempty_line_count`：去除行首尾空白后仍有内容的行数。
- `constraints`：仅检查题目明确给出的 `max_characters` 或 `exact_nonempty_lines`。每项返回 `expected`、`observed`、`satisfied`。未给限制时为空，不自动施加长度目标。

这些数据是输出尺寸与格式约束的证据，没有总通过分。字符数更少不代表更好的思考；空答案也可能满足字符上限。表格内容、只给代码、事实正确性、必要追问及推理质量仍需结合任务检查。真实 token 数与耗时只能使用运行器实际提供的数据；没有则记为未测量。

在本目录中调用示例：

```python
from check_objective import check_output

result = check_output(answer, constraints={"max_characters": 100})
```

调用兼容说明：旧的 `check_output(text, problem_type)` 仍可调用，但 `problem_type` 只为迁移保留，不改变测量。返回结构有意不兼容旧评分字段，调用方必须按 `schema_version` 处理。`names_main_contradiction`、`has_falsifiable_hypothesis`、`fabricated_sources` 和 `avoided_unneeded_gate` 已移除。原正则最多检测某种文字样式，尤其 `fabricated_sources == 0` 从来不能证明没有编造来源。历史产物保留原样，不将旧值映射成新的正确性判断。

## 有限的对照运行协议

1. **冻结材料。** 记录运行日期、技能提交号或内容快照哈希、实际加载的引用文件、题库与本 rubric 的版本或哈希。工作区有未提交改动时保存实际内容快照，仅记 Git HEAD 不够。每次修改后用新的运行标识，保留旧样本。
2. **保持运行条件可比。** 记录实际模型标识、可用的推理强度、温度或随机种子、宿主系统指令、工具权限、上下文和长度限制；不可控制或未知的设置写明。使用新会话，避免前题污染。不要向作答者提供评分依据或期望答案。
3. **按题运行。** 首轮只发送 `prompt`，使 `files` 列出的文件可读取。存在 `follow_up_prompts` 时，在同一会话依次发送，保留每轮完整答复；若有 `follow_up_files`，在发送该轮 prompt 时才提供其同索引文件。题目中的数据是给定场景，不需要查找虚构公司的真实资料；历史或当前事实题的检索权限和来源截止时间应保持一致。未跑后续轮不能称为通过多轮题。
4. **设置对照。** 比较当前技能、冻结的旧版技能和不加载该技能的普通回答。普通回答组删除 `/mzt` 激活前缀，保留相同任务内容。第13题的模式命令仅比较有该命令语义的技能版本，普通回答组不参与命令状态评分。没有旧版或普通回答对照时，明确报告这是覆盖检查，不是改善证明。
5. **控制规模并重复。** 先每题一次发现覆盖缺口；对出现失败、版本差异或不稳定的题目，每组使用相同设置独立重复至少5次。报告全部样本和失败比例，不只选最好的一次。若声称整体稳定优于基线，应对全套题使用同样的重复安排；几道 smoke 的结果不能支撑该结论。
6. **盲评并核对。** 隐藏版本标签并打乱样本顺序。Reviewer 依据题目、事实和产物评分；条件允许时由另一位 reviewer 复核关键分歧。代码题执行有意义的小样例；来源真实性通过实际来源核对，不看引用外观。记录评价者是人还是模型、是否与生成者相同。

结果记录保留运行信息、完整可见答复、每轮机械测量、逐题评分及理由即可，不需要新建评测平台。对照组某轮自行选择工具或追问是可观察行为的一部分；若需要额外用户信息，所有组按同一预设补充信息规则处理，不能只给某组有利线索。

## 第 15—17 题的材料供给与判断

这三题使用有限的虚构文件集，检验面对不完整的争论片段时，是否实际查阅可取得的背景和原始材料。题面和目录不附正确答案或审查要求。所有 `files`、`follow_up_files` 路径相对于本评测目录，复制到独立运行目录后保持相对路径不变；目录内的 Markdown 链接相对于所在文件解析。

作答者仅取得当轮自然任务、可用工具以及当前轮允许的文件。不要提供完整 `evals.json`、rubric、reviewer 提示或上一轮运行样本。使用技能的组可以获得待评技能入口与其方法参考文件，但不要因此顺带暴露题库、评分材料和未到供给轮次的 fixtures。保留实际读取记录与每轮完整答案，检查是否读取了其他题、后续材料或评分文件；发生泄露的样本作废，不计作技能成功。

最小材料如下：

| 题目与轮次 | 应提供的材料 |
|-----------|---------------|
| 第 15 题 | `prompt` 和 `files` 中的 5 个文件，包含索引、预算通知、调整草案、公开讨论和会议记录 |
| 第 16 题首轮 | `prompt` 和 `files` 中的 4 个文件，包含索引、收费通知、原始建议和初次评论 |
| 第 16 题第二轮 | 等首轮完整结束后，才复制 `follow_up_files[0]` 中的 `04-follow-up.md`，并发送 `follow_up_prompts[0]`；保留同一会话的首轮上下文 |
| 第 17 题 | `prompt` 和 `files` 中的 5 个文件，包含索引、扩展草案、合同登记、听证记录和帖子 |

第 16 题不能直接复制整个 fixture 子目录后仅要求作答者暂时不读第四份文件。后续文件应在首轮可用目录中不存在，首轮索引也不列出它。若宿主无法真正限制对原始仓库的访问，应明确记录这个限制，并通过工具轨迹核对未读取原始目录或其他位置的后续文件；不能宣称已实现严格访问隔离。把澄清与初始材料一起供给，只能检查单轮材料综合能力，不能替代本题的真实修正测试。

具体判断应落在以下可见行为上，不要求答案使用相应标题：

- **实际调查。** 第 15 题应查阅支撑政策起因、原始主张与现有结果的正文；第 16 题应查阅原始建议和评论，后轮再读澄清；第 17 题应查阅合同、登记及收费材料。仅打开索引、声称已调查、列出未来调查计划，均不能算完成。文件可读却不读，直接沿题面片段评价整个事件，记录调查任务失败。若运行环境缺失读取能力，记为该能力未测量；不得当作成功，也不要把宿主缺陷混作模型失败。
- **判断对象。** 第 15 题把暂停新增采购等同于取消现有数字服务，或把部门草案的取舍说成预算通知强制要求，属于关键事实错误。第 16 题把取消价差当作取消预约通道，属于语义对象错误。这些错误不能被一般性的数字化价值、预约价值或公平性讨论抵消。准确识别偏移不以断言评论者故意操纵为前提。
- **结果范围。** 第 15 题会议仅作阶段性安排，长期效果未发生；不能写成节支和服务改善已经验证。第 16 题第二轮只有新的意见和自述，不提供需求或排班成效数据；不能把可能机制写成实证结果。
- **利益证据。** 第 17 题应明确使用持股、顾问费和平台扩展收费之间的关系，考察不同摊主受到的影响。只告诫不要猜动机、只重复当事人自称为了低收入群体，均未完成核心任务。把供应商营业收入当成个人净收益、把免固定费写成免全部收费，是实质错误。承认这些经济联系，仍不足以认定其受雇作这次发言、蓄意损害摊主或受到境外指使；把匿名家庭传闻当作已证实事实，单独记录失败。
- **真实修正。** 第 16 题对比两轮答案：后轮应更新对周远当前立场的评价，审视其新的价格激励论点，并保留对初次转述失真的判断。只加一句收到新信息，却继续把已被纠正的说法当作其当前立场，属于未修正；因为对方改口就撤销所有此前判断，或因为他先前出错就拒绝审视新论点，同样不合格。首轮无须预测尚未提供的澄清。

每题至少保留支撑判断的读取动作、相关文件位置和答案片段。读取文件数量本身没有奖励，打开全部材料也不能抵消对材料的误解。合理地支持、反对或有条件接受某一政策，都可能通过；关键在于是否调查、是否评价了真实主张，以及证据是否实际改变判断。

## 覆盖与局限

题库保留原 14 题，覆盖具体组织决策、多轮反证、直接事实与代码、用户指定表格和简答、需要充分解释的复杂案例、会话开关与既定任务方向；第 15—17 题补充事件起因调查、概念替换与后续澄清、真实利益联系与无依据动机推断的区分。共同利益分歧不应被制造成敌我关系；存在实质利益关系时也不能回避调查，信息缺失不应被填成虚构事实。

这仍是有限题库。少量样本不能证明通用收益，模型评分也可能偏爱某种文风；只看可见行为无法断定内部如何思考，`on/off` 的文字回应也不能证明宿主实现了持久状态。应使用真实任务中的失败继续修正，并保留模型、上下文和检索条件带来的不确定性。

历史 iteration 的分数使用旧题目焦点、旧指标或不同运行设置，不能与 v2 分数直接比较。旧版长报告可作为已发生的行为证据，是否改进仍需在可比条件下观察新旧实际答复。脚本单测通过仅说明测量器按其契约工作，不代表技能行为评测通过。

脚本检查命令（仓库根目录）：

```bash
python3 -m pytest mzt/evals/test_check_objective.py -q
python3 -m json.tool mzt/evals/evals.json > /dev/null
```
