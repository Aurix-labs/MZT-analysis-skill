## 结论与变更

第二轮的显式调用存在额外播报：用户要求只给数字、代码、表格或译文，完整公开答复仍会先说明使用技能。本轮修复了这一可复现问题；最终版本的60个格式样本全部通过，10个复杂任务样本及1个五轮模式样本也通过。该结果说明本次调用修复有效，不证明23篇方法论相对无技能有额外收益。

运行包只变更两个文件：

- [SKILL.md](../../SKILL.md)：在发现阶段可见的描述和正文中明确“只给成果”约束覆盖最终答案之前的公开消息；说明完整正文的注入与读取要求，以及原生调用和兼容文本的区别。
- [agents/openai.yaml](../../agents/openai.yaml)：增加包含 `$mzt` 的技能界面默认提示。没有修改自动触发策略。

23篇方法正文、参考材料及 README 均未改动。修复保留按问题自由思考的设计，没有新增固定步骤、回答模板或方法数量要求。

## 调用机制与失败定位

Codex 提供技能选择器和 `$` 提及；App Server 的 `turn/start` 可以同时接收文本与结构化 `skill` 项。官方文档建议显式调用时携带结构化项，以便提供完整技能正文；仅有文本仍可能依赖模型自行查找。[技能文档](https://learn.chatgpt.com/docs/build-skills)、[App Server 文档](https://learn.chatgpt.com/docs/app-server)

`/mzt` 是本技能支持的文本约定，本文件没有向宿主注册斜杠命令。输入 `/mzt` 或裸 `$mzt`，本身都不足以证明正文已加载。本轮分别核查实际注入和实际读取，不以 agent 自称使用、答案正确或是否再次执行 `cat` 代替加载证据。

发现描述在读取正文前已经可见。第一候选只增加正文输出约束、调用说明及界面元数据：原生路径改善，但文本路径仍大量先播报。第二候选在描述中补上同一严格输出边界后，本轮两个路径均通过。因此不能只依赖正文约束阻止加载前已经发生的说明，也不能仅更换调用写法就认为问题消失。

这是两步候选试验支持的局部定位；并未把正文、元数据、描述中的每个句子拆成独立随机实验，不能宣称识别了所有宿主中的唯一原因。
